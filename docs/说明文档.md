# Minecraft Ore Scan 源码说明

本目录保存了本次 Minecraft Java 1.21.1 世界生成、矿物扫描和 Excel 导出的关键源码。

代码完成的流程是：

1. 使用原版服务端按 seed 创建或加载世界。
2. 通过 RCON 分批执行 `/forceload`，生成指定维度的区块。
3. 读取 Anvil `.mca` region 文件中的压缩 NBT 数据。
4. 解码区块 section 的 `block_states.palette` 和 `block_states.data`。
5. 找出指定矿物方块的世界坐标。
6. 按到指定原点的三维直线距离排序。
7. 输出包含 `X、Y、Z、矿物名称、距离` 的 Excel 文件。

## actual-run 文件

这些文件是本次实际生成和扫描任务中使用的固定范围脚本，参数写在源码常量中，适合复现本次结果。

### `actual-run\pregen.py`

基础的本机 RCON 客户端和主世界预生成逻辑。

- 建立 RCON TCP 连接并完成 Source RCON 认证。
- 发送命令并读取服务端响应。
- 读取 `world\region` 的 Anvil location header。
- 判断某个区块是否已经保存。
- 按 25×10 区块批次生成主世界。
- 默认目标范围是区块 `-50..49`，即 100×100 区块。
- 默认 RCON 密码是源码中配置的临时本机密码，使用前应自行修改。

它是 `pregen_300.py`、`pregen_nether_500.py` 和部分 Excel 脚本的依赖模块。

### `actual-run\pregen_300.py`

调用 `pregen.py` 的 RCON 和 region 检查函数，生成原点附近 300×300 个主世界区块。

- 区块范围：`X/Z = -150..149`。
- 目标数量：90,000 个区块。
- 使用 25×10 区块批次，每批 250 个区块。
- 对已经存在的区块自动跳过。
- 生成过程中每批执行 `save-all flush`，然后解除该批的强制加载。

脚本使用相对路径 `world`，必须从包含 `world` 和服务端配置的目录运行。

### `actual-run\pregen_nether_500.py`

下界专用预生成脚本。

- 维度：`minecraft:the_nether`。
- region 路径：`world\DIM-1\region`。
- 区块范围：`X/Z = -250..249`。
- 目标数量：250,000 个区块。
- 通过 `execute in minecraft:the_nether run forceload ...` 确保命令作用于下界。
- 生成后检查下界 region 文件，而不是主世界 region 文件。

该脚本依赖同目录下的 `pregen.py` 中的 RCON 类。运行前必须启动开启本机 RCON 的原版服务端。

### `actual-run\scan_diamonds.py`

本次矿物扫描使用的 Anvil/NBT 扫描器，默认目标为：

- `minecraft:diamond_ore`
- `minecraft:deepslate_diamond_ore`

主要职责：

- 读取 `.mca` region 文件头，定位每个区块的 sector。
- 解压 gzip、zlib 或未压缩的区块 payload。
- 使用 `nbtlib` 读取区块 NBT。
- 遍历 `sections`、`block_states`、`palette` 和 `data`。
- 将 section 内的局部坐标转换为世界 X/Y/Z。
- 可选地将相邻的矿石方块合并为矿脉连通组。

其中的 packed block-state 解码使用 Minecraft 的正确规则：

```text
bits = max(4, ceil(log2(palette_size)))
values_per_long = 64 // bits
long_index, slot = divmod(block_index, values_per_long)
offset = slot * bits
```

不要将 `data` 当作可以跨 long 连续切割的 bit stream，否则 palette 位数为 5、6、7 等情况会产生错误坐标和错误矿物数量。

### `actual-run\export_diamonds_excel.py`

调用 `scan_diamonds.py` 扫描主世界并生成钻石 Excel。

- 固定范围：区块 `-150..149`。
- 固定路径：`world\region`。
- 固定输出：`diamonds_sorted.xlsx`。
- 距离原点：`(0,64,0)`。
- 距离公式：`sqrt(X^2 + (Y-64)^2 + Z^2)`。
- 每个钻石矿石方块写一行。
- 超过 Excel 单工作表限制时拆分工作表。

### `actual-run\export_nether_debris_excel.py`

调用 `scan_diamonds.py` 的 NBT 扫描逻辑，但将目标切换为 `minecraft:ancient_debris`。

- 固定维度：下界。
- 固定路径：`world\DIM-1\region`。
- 固定范围：区块 `-250..249`。
- 固定输出：`nether_ancient_debris_sorted.xlsx`。
- 显示名称：`远古残骸`。
- 距离原点：下界 `(0,64,0)`。

### `actual-run\localize_diamonds_excel.py`

直接修改 Excel 的 OOXML 压缩包中的 worksheet XML，把已有类型文本替换为中文：

```text
minecraft:deepslate_diamond_ore -> 深板岩钻石
minecraft:diamond_ore           -> 钻石
```

它不重新计算坐标、距离或排序，只修改显示文本。使用前应先备份输入 `.xlsx`，并通过临时文件输出后再替换原文件。

## generic 文件

这些文件是更推荐的新任务入口，可以通过命令行参数复用到不同版本、seed、维度、范围和矿物。

### `generic\pregenerate.py`

通用原版区块预生成器。

关键参数：

```text
--level-name       服务端的 level-name 目录，默认 world
--dimension        minecraft:overworld / minecraft:the_nether / minecraft:the_end
--min-chunk        最小区块坐标
--max-chunk        最大区块坐标
--x-width          单批 X 方向区块宽度，默认 25
--z-height         单批 Z 方向区块高度，默认 10
--rcon-host        RCON 地址，默认 127.0.0.1
--rcon-port        RCON 端口，默认 25575
--rcon-password    临时 RCON 密码
--min-free-gb      最低保留磁盘空间，默认 8 GB
--stop-after-complete  完成后发送 stop
```

默认批次面积是 `25 × 10 = 250`，低于原版 `/forceload` 的 256 区块限制。它会：

1. 计算目标批次。
2. 检查 location header 中已经保存的区块。
3. 通过 RCON 添加当前批次的强制加载。
4. 周期性执行 `save-all flush`。
5. 等待批次所有区块出现保存记录。
6. 移除该批次的强制加载。
7. 继续下一批。

示例：

```powershell
cd "D:\Minecraft Ore Scan Src"
python generic\pregenerate.py `
  --level-name world `
  --dimension minecraft:the_nether `
  --min-chunk -250 `
  --max-chunk 249 `
  --rcon-password seedworld-local `
  --stop-after-complete
```

服务端应从同一目录启动，且 `server.properties` 临时设置：

```properties
enable-rcon=true
rcon.password=seedworld-local
rcon.port=25575
```

完成后必须关闭 RCON、清空密码、恢复正常 watchdog 设置。不要把临时 RCON 暴露到公网。

### `generic\scan_to_excel.py`

通用矿物扫描和 Excel 导出器。

关键参数：

```text
--world             世界目录，默认 world
--dimension         目标维度
--min-chunk         最小区块坐标
--max-chunk         最大区块坐标
--ore ID=名称       可重复指定多个矿物
--origin X,Y,Z      距离原点，默认 0,64,0
--output 文件.xlsx  输出文件
```

钻石示例：

```powershell
python generic\scan_to_excel.py `
  --world world `
  --dimension minecraft:overworld `
  --min-chunk -150 `
  --max-chunk 149 `
  --ore "minecraft:diamond_ore=钻石" `
  --ore "minecraft:deepslate_diamond_ore=深板岩钻石" `
  --origin 0,64,0 `
  --output diamonds_sorted.xlsx
```

远古残骸示例：

```powershell
python generic\scan_to_excel.py `
  --world world `
  --dimension minecraft:the_nether `
  --min-chunk -250 `
  --max-chunk 249 `
  --ore "minecraft:ancient_debris=远古残骸" `
  --origin 0,64,0 `
  --output nether_ancient_debris_sorted.xlsx
```

输出列为：

```text
X | Y | Z | Mineral | DistanceTo_(X,Y,Z)
```

距离按三维欧氏距离计算，并按 `(distance_squared, Y, X, Z)` 排序。每个方块一行，不自动合并矿脉。Excel 每个 worksheet 最多写入 1,048,575 行数据，超出后自动创建 `Minerals_2`、`Minerals_3` 等工作表。

## 依赖和运行顺序

安装 Python 依赖：

```powershell
python -m pip install nbtlib openpyxl
```

推荐顺序：

1. 下载指定版本的 Mojang 原版 `server.jar` 并校验 SHA-1。
2. 配置 seed、`level-name`、`eula=true` 和临时本机 RCON。
3. 启动服务端并等待 `Done` 与 RCON listener。
4. 运行 `generic\pregenerate.py`。
5. 独立检查每个目标区块的 region location entry，确认缺失数为 0。
6. 运行 `generic\scan_to_excel.py`。
7. 检查 Excel 的首行距离、总行数、sheet 数和 ZIP/OOXML 完整性。
8. 保存并干净停止服务端，关闭 RCON。

## 重要限制

- `server.properties` 的 seed 只对新建世界生效；已有 `level.dat` 不会被 seed 设置覆盖。
- 预生成的是区块方形，不是精确的任意方块多边形。区块边界外的方块可能也被同一个区块包含。
- Anvil region 文件必须在服务端保存后再扫描，避免读取正在写入的压缩 payload。
- 生成大范围区块需要很长时间、较多磁盘和内存。开始前检查资源，过程中不要强制终止 Java 服务端。
- 只在本机使用临时 RCON；生成结束后恢复 `enable-rcon=false`。
- 中文脚本和文档应以 UTF-8 保存。若 Windows PowerShell 显示乱码，先确认终端编码和文件编码，不要把源码中的中文替换成问号。
